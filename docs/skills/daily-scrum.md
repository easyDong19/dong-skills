# daily-scrum

그날의 커밋 · PR을 모아 **비개발자도 읽을 수 있는 스크럼 메모**로 만든다. 기본 출력은 노션 같은 스크럼 테이블의 '오늘 한 일' 셀에 그대로 붙일 수 있는 평문이다.

## 언제 쓰나

- **매일 아침 데일리 스크럼.** 어제 커밋을 다시 읽으며 무엇을 했는지 떠올리는 시간을 줄인다.
- **기획 · 디자인 · 경영이 같이 보는 테이블.** "reducer로 상태 구현" 대신 "회원가입 화면을 단계별로 넘어가게 만듦"처럼 기능 단위로 쓴다.
- **주간 보고에 붙일 작업 설명.** "자세히" 모드는 배경 → 작업 → 검증으로 풀어 쓴다.

## 이렇게 부른다

```
오늘 한 일 데일리 스크럼용으로 정리해줘
```
```
어제 뭐 했는지 스탠드업용으로
```
```
이 PR 위클리에 붙일 거라 자세히 써줘
```

## 결과 예시

입력 (그날의 커밋, 레포 두 곳):

```
web     feat(record): 기록 카드 클릭 시 상세로 이동
web     fix(auth): 로그아웃 후 이전 사용자 캐시 초기화
web     refactor(upload): 저장 파일명에서 내부 id 제거
mobile  feat(record): 기록 필터 화면 추가        (QA 리포트 아티팩트 있음)
```

출력 (코드블록째 셀에 붙인다):

```
습관 기록 (웹)
• 오늘 기록 카드를 누르면 상세 화면으로 넘어가게 함
• 로그아웃 후 다른 계정으로 들어가도 앞 사람 데이터가 보이던 문제 해결
• 프로필 사진 업로드
　　◦ 저장되는 파일 이름에서 내부 관리번호를 빼 사람이 읽을 수 있게 함

습관 기록 (앱)
• 기록 필터 화면 만들기
　　◦ 화면 캡처: https://claude.ai/artifact/<그날 만든 QA 리포트>

참조
https://github.com/<owner>/<repo>/pull/165
https://github.com/<owner>/<repo>/pull/159
```

규칙 몇 가지:

- 셀은 마크다운을 렌더하지 않는다. `**볼드**`, `- ` 불릿, `#` 헤더 대신 `•` · `◦`와 줄바꿈만 쓴다.
- `◦` 앞 들여쓰기는 **전각 공백(U+3000) 두 칸**이다. 일반 공백은 노션 셀에 붙일 때 지워진다.
- 레포 약칭(`web`, `mobile`) 대신 제품 이름을 쓴다.
- 사람이 열어 볼 링크(QA 리포트 등)는 `참조` 줄이 아니라 해당 항목 아래에 붙인다.

## 쓰지 않는 경우

- 경영진용 개조식 보고서
- PR 하나를 코드 수준에서 설명: [explaining-with-domain-context](explaining-with-domain-context.md)
