# 기술 문서 정보 구조 리뷰

## Overview

문서 초안·목차를 5개 정보 구조 원칙으로 진단하고, 모든 개선 옵션을 통합한 **하나의 최종 개선 목차**를 제시한다. 문장 다듬기가 아니라 구조(페이지 분리·순서·제목 체계)가 대상이다.

## When to Use

- 문서 초안/목차를 주며 "구조 어때?", "어떻게 나눌까?", "목차 피드백 줘"라고 할 때
- 문서가 너무 길거나 주제가 섞여 페이지 분리를 고민할 때
- 새 문서의 목차 설계를 시작할 때

**When NOT to use**: 문장 단위 윤문·맞춤법은 doc-sentence-polish 스킬 사용. 문서 유형 선택은 choosing-doc-type 사용.

## 진단 절차

사용자가 문서 목표·독자·문제점을 줬으면 그것을 최우선 기준으로 삼는다. 안 줬으면 초안에서 추론하되, **추론했음을 결과에 명시**한다.

## 5개 원칙 체크리스트

| # | 원칙 | 체크 |
|---|------|------|
| 1 | 한 페이지 하나의 목표 | H4(####) 이상 깊이 → 문서 분리 신호 / 개요가 핵심 목표를 전달하는가 / 너무 많은 개념이 혼합되지 않았는가 |
| 2 | 개요 빠트리지 않기 | 시작 부분에 명확한 요약 개요가 있는가 / "이 문서를 읽으면 무엇을 얻는가"가 바로 이해되는가 |
| 3 | 예측 가능한 구조 | 동일 수준 제목이 일관된 패턴인가 / 기본 개념→상세 내용 점진 배치인가 / 용어가 일관되는가 |
| 4 | 가치를 먼저 제공 | 도입부에 독자 이점(문제 해결 효과)이 명시됐는가 / 기능·세부 설정은 후순위인가 |
| 5 | 효과적인 제목 | 핵심 키워드 포함 / 30자 이내 / 동사형·명사형 스타일 일관 / 평서문 형태(의문문 지양) |

## 출력 형식 (필수)

1. **원칙별 진단** — 5개 원칙 각각에 대해 통과/문제점을 구체 위치(섹션명)와 함께 제시
2. **최종 개선안 (하나로 통합)** — 개선 옵션을 나열만 하지 말고, 모두 반영한 **단일 개선 목차**를 markdown 목차 형태(`#`/`##`/`-`)로 제시. 페이지 분리가 필요하면 문서별 목차로 나눠 제시
3. **변경 이유 요약** — 주요 변경마다 어떤 원칙 때문인지 한 줄씩

## Quick Reference

| 증상 | 처방 |
|------|------|
| H4 이상 중첩 | 별도 페이지로 분리 (원칙 1) |
| 개요 없이 본론 시작 | 문서 첫머리에 2-3문장 개요 추가 (원칙 2) |
| 설정 나열 후 효과 설명 | 가치·이점을 도입부로 이동 (원칙 4) |
| 제목이 문장형/의문형 혼재 | 명사형 또는 동사형으로 통일 (원칙 3·5) |
| 같은 개념에 용어 2개 | 하나로 통일 (원칙 3) |

## Common Mistakes

- 개선 옵션 A/B/C를 나열하고 끝내기 — 반드시 **하나의 통합 개선안**으로 수렴시킨다
- 구조 대신 문장 표현을 고치기 — 이 스킬의 범위 밖
- 독자·목표를 확인하지 않고 진단하기 — 추론했으면 추론임을 밝힌다
- 원본 목차의 좋은 부분까지 갈아엎기 — 문제 없는 구조는 유지한다
