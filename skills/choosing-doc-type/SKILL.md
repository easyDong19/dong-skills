# Choosing Doc Type — 문서 유형부터 정한다

## Overview

기술 문서의 품질 사고는 대부분 "잘못 쓴 문장"이 아니라 **"한 문서에 여러 유형을 섞은 구조"**에서 난다. Diátaxis 프레임워크의 4유형(학습 / 문제 해결 / 참조 / 설명) 중 **하나를 먼저 정하고, 그 유형의 규칙으로만 쓴다.**

**핵심 규칙: 한 문서 = 한 유형.** 두 유형이 필요하면 문서를 쪼개고 서로 링크한다.

## 판정 — 2축 결정표

독자에 대해 두 가지만 판단하면 유형이 나온다:

|  | 독자가 **실행**하려 한다 (손) | 독자가 **이해**하려 한다 (머리) |
| --- | --- | --- |
| **배우는 중** (학습 맥락) | **학습(튜토리얼)** — 따라 하면 완성되는 수업 | **설명(explanation)** — 배경·원리·설계 이유 |
| **일하는 중** (작업 맥락) | **문제 해결(how-to)** — 목표 달성 절차 | **참조(reference)** — 정확한 사실 조회 |

판정 질문 2개:
1. 독자는 지금 **배우러** 왔는가, **일하다가** 왔는가?
2. 독자가 원하는 것은 **실행 결과**인가, **이해**인가?

## 입력은 맥락에서 추론한다

문서 목표·독자 수준·프로젝트 상황·제약은 **사용자에게 설문하지 말고** 대화 맥락·레포·git 히스토리에서 먼저 추론한다. 유형 판정을 가르는 정보(특히 독자와 목표)가 정말 불명확할 때만 한 번에 묶어서 질문한다.

## 혼합 신호 → 쪼개라

아래 신호가 보이면 한 문서가 아니라 **문서 세트**다:

- 제목·목차에 "왜"와 "어떻게"가 같이 들어감 → 설명 + 문제 해결, 2개로 분리
- "개념도 알려주고 바로 쓸 수 있게" → 설명(또는 학습) + 참조, 분리 후 상호 링크
- 인수인계(handover) 문서 → 기본은 **설명**(구조와 결정 이유). 절차가 필요하면 how-to를 별도 문서로 두고 링크. 시그니처·옵션 나열이 필요하면 참조를 분리
- FAQ·트러블슈팅 섹션이 본문의 1/3 이상 → 문제 해결 문서로 독립

복수 유형을 제안할 때도 **주 문서 1개를 명시**하고 나머지는 "분리 권장"으로 표기한다.

사용자가 "파일 하나로"를 명시적으로 요구하면 유형을 섞지 말고 **파일 1개 안에서 유형별 섹션으로 분리**한다 — 섹션 시작마다 `[유형: 설명]`처럼 라벨을 붙이고, 목차에서 "급하면 N번으로 바로 가라"식 진입점을 안내한다.

## 유형별 작성 체크리스트

### 학습 (튜토리얼) — 초심자가 따라 하며 능력을 얻는다
1. 학습 목표와 완료 후 얻는 능력 명시
2. 사전 준비·환경 설정
3. 단계마다 "무엇을·왜" 설명, 난이도 점진 상승
4. 모든 예제는 실제 실행 가능해야 함
5. 마지막에 자주 막히는 지점과 해결책

### 문제 해결 (how-to) — 일하는 사람이 목표를 달성한다
1. 문제 상황 또는 작업 목표를 첫 줄에 정의
2. 필요한 배경지식은 최소만, 나머지는 설명 문서로 링크
3. 단계별 절차 + 실행 가능한 명령어·코드
4. 환경별 차이(OS·버전) 주의점
5. 해결 원리는 짧게 — 길어지면 설명 문서로 분리

### 참조 — 정확한 사실을 빠르게 찾는다
1. 간결한 개요
2. 구문·파라미터(타입·기본값·필수 여부)·반환 값
3. 기본 사용 예제 (튜토리얼식 서사 금지)
4. 관련 API·컴포넌트 연계
5. 주의 사항·제한. **일관된 구조**가 생명 — 항목마다 같은 틀

### 설명 — 원리·배경·설계 이유를 이해시킨다
1. 등장 배경과 해결하려는 문제
2. 동작 원리 상세
3. 다른 접근과의 비교·트레이드오프 (기각된 대안 포함)
4. 다이어그램 등 시각 자료
5. 실제 사용 사례. 절차서가 되지 않게 — 단계 나열이 시작되면 how-to로 분리

## 공통 규칙

- 이모지 사용 금지
- 유형 결정과 근거(2축 판정)를 사용자에게 한 줄로 보고한 뒤 목차를 잡는다
- 급하다는 요청은 유형을 섞을 이유가 아니라 **범위를 줄일 이유**다

## Red Flags — 멈추고 유형부터 다시

- 목차를 먼저 잡고 있음 (유형 미결정)
- 제목에 "왜, 어떻게"가 함께 있음
- "주니어니까 다 넣어주자"
- "급하니까 한 문서에 합치자"
- "인수인계니까 전부 담아야지"

## Common Mistakes

| 실수 | 교정 |
| --- | --- |
| 독자 수준을 분량 조절에만 사용 | 독자 수준은 **유형 선택**의 1차 입력이다 |
| 참조 문서에 서사·튜토리얼 흐름 | 참조는 조회용 — 항목별 동일 구조 유지 |
| 설명 문서가 절차서로 변질 | 단계 나열 시작 = how-to 분리 신호 |
| 4축 정보를 사용자에게 설문 | 맥락에서 추론, 불명확한 것만 질문 |
