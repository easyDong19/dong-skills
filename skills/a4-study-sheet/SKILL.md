# a4-study-sheet

시험장·면접장에 **종이로 들고 들어가 마지막 5분에 훑는** 자료를 만든다.
화면용 학습자료(study-explainer)와 목적이 다르다: **흑백 프린터로 뽑아 한 장에 담기는 것**이 전부다.

## 언제 쓰나

- "A4로 정리해줘 / A4 한 장으로 / 인쇄해서 볼 거야 / 흑백으로"
- 시험·면접·발표 직전 압축 요약(치트시트)
- 이미 대화에서 배운 내용을 손에 들 형태로 굳힐 때

화면에서 스크롤하며 볼 인터랙티브 자료·비유 애니메이션은 `study-explainer`를 쓴다.

## 절대 규칙

1. **로컬 파일로만.** `Artifact` 도구로 발행하지 않는다. 로컬에 `.html`을 쓰고 파일 경로를 안내한다.
2. **흑백 전용.** 색으로 정보를 구분하지 않는다. 컬러 프린터가 없다고 가정한다.
3. **A4 1장.** 넘치면 색이 아니라 **글을 줄인다.** 요약이 목적이다.

## 저장 위치

우선순위대로 정한다. 폴더가 없으면 만든다.

1. **사용자가 위치를 지정했으면** 거기에 쓴다.
2. **학습 여정(study repo) 안이면** 그 여정 폴더의 `A4정리/`에 모은다. (예: `<여정>/A4정리/<주제>_핵심정리.html`)
3. **그 외 아무 프로젝트면** 현재 작업 폴더 기준 `A4정리/`(또는 사용자가 부르는 이름)에 쓰되, 애매하면 한 번 물어본다.

파일명은 `<주제>_핵심정리.html`. 프로젝트에 자체 규칙(CLAUDE.md 등)이 있으면 그 규칙을 우선한다.

## 흑백 디자인 규칙 (색 대신 이걸로 구분한다)

| 구분 수단 | 쓰는 법 |
|---|---|
| 테두리 굵기 | 강조 박스 `1.5px solid #000`, 일반 `1px`, 보조 `1px dotted/dashed` |
| 음영 3단 | `#efefef`(약) / `#dcdcdc`(중) / `#000`+흰글씨(강). 그 이상 쓰지 말 것 |
| 굵기·밑줄 | 핵심어 `<b>`, 형광펜 대신 `box-shadow:inset 0 -6px 0 #dcdcdc` 로 회색 언더라인 |
| 대비 반전 | 두 항목 대조 시 한쪽 헤더는 검정 바탕 흰 글씨, 다른 쪽은 흰 바탕 검정 글씨 |
| 다이어그램 | 어두운 배경 금지(토너 낭비). **밝은 배경 `#efefef` + 검정 테두리 + monospace** |

- 이모지는 흑백에서도 형태로 읽히면 허용(🚂🚗 등). 색으로만 의미가 나는 아이콘은 금지.
- 정보 위계는 섹션 번호 칩(`background:#000; color:#fff`), 굵은 h2 밑줄, 표로 만든다.

## 인쇄 CSS 필수 뼈대

```css
html{ -webkit-print-color-adjust:exact; print-color-adjust:exact; }
.page{ width:210mm; min-height:297mm; margin:8mm auto; padding:12mm 13mm; background:#fff; }
@page{ size:A4; margin:0; }
@media print{ body{background:#fff;} .page{margin:0; box-shadow:none; width:auto; min-height:auto;} }
```

- 본문 폰트 10~10.5px, 줄간 1.45~1.5. 한글 폰트 스택: `"Pretendard","Apple SD Gothic Neo","Malgun Gothic",system-ui,sans-serif`.
- 한 장에 안 들어가면: 밀도를 올리기 전에 **먼저 내용을 버린다.** 폰트 줄이기·그리드 욱여넣기는 최후의 수단이다(그게 "산만함"의 원인).

## 정돈되게 쓰는 법 (밀도보다 읽힘) ★

**가장 흔한 실패 = 활자가 산만하다.** 원인은 늘 같다: 매 섹션마다 새 2~3단 그리드·mono 박스를 즉흥으로 짜서 쌓는 것. 방지법:

1. **컴포넌트를 재사용한다.** 매번 새 레이아웃을 발명하지 말고 아래 **고정 어휘**만 돌려쓴다. 페이지 전체가 같은 문법으로 보여야 정돈된다.
   - `.oneline` — 검정 테두리 한 줄 정의/핵심 박스
   - `h2` — 밑줄(`border-bottom:2px`) + 번호칩(`.n`). 모든 섹션 헤더는 이 하나로 통일
   - `table` — 비교·대응은 **2~3단 카드 그리드 대신 풀폭 표**로. 첫 칸은 `td.k`(회색 라벨)
   - `.diagram` — 밝은 배경 + monospace 흐름도. **페이지당 1~2개까지만**
   - `.key` — 즉시 발화용 인용(밑줄 제목 + 문장)
   - `.warn` — 마지막 점선 "하지 말 것"
2. **한 섹션 = 한 아이디어 = 한 표현.** 한 섹션 안에 그리드+mono+표를 겹쳐 넣지 않는다. 산문 한 줄로 되면 산문으로.
3. **여백을 지킨다.** 섹션 간 `margin-top:15px` 안팎, 줄간 1.48. 빈틈을 글로 메우려 하지 말 것 — 남는 여백은 정돈의 신호지 낭비가 아니다.
4. **섹션은 4개 안팎.** 6개를 넘기면 프레임이 아니라 교재가 된다. 목적(마지막 5분 훑기)에서 멀어진 섹션부터 버린다.
5. **다른 시트가 있으면 그걸 바탕으로.** 같은 프로젝트에 기존 `A4정리/*.html`이 있으면 새로 디자인하지 말고 그 CSS·컴포넌트를 그대로 가져와 톤을 맞춘다.

> 참고 기준선: `~/woodie/study/hyundai-job-interview/A4정리/무인이송_핵심정리.html` — 위 어휘가 실제로 적용된 정돈 예시.

## 내용 구조 (요약본의 뼈대)

1. **제목 + 한 줄 정의** (맨 위 박스 하나. "이거 하나면 절반")
2. **3~4개 핵심 섹션.** 각 섹션은 번호 칩 + h2, **한 섹션에 한 표현**(풀폭 표를 2단 카드보다 우선).
3. **"한 문장 답" / "면접 마무리 한 수"** 같은 즉시 발화용 인용 박스(검정 테두리).
4. **⚠ 하지 말 것** (점선 박스, 마지막). 시험이면 함정, 면접이면 금기.
5. 맨 아래 출처·날짜 한 줄.

## 절차

1. 대상 주제와 저장할 여정 폴더를 확인한다. (대화에 이미 있으면 묻지 않는다.)
2. `A4정리/` 폴더를 만들고 `<주제>_핵심정리.html`을 쓴다.
3. `SendUserFile`로 `display:"render"` 하여 보여준다. 사용자에게 **브라우저 Ctrl/Cmd+P로 한 장에 맞는지** 확인을 요청한다.
4. 넘치거나 남으면 글을 줄이거나 밀도를 조정한다. 색을 늘려 해결하지 않는다.
5. 승인받으면 그대로 둔다(이미 로컬 저장됨). 여정 로드맵/index에 링크를 걸지는 별도로 묻는다.
